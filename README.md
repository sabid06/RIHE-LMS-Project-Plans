## Folder structure

The folder names follow the layout of the reference ZIP. The `02-WBS-Schedule`, `03-Resources-and-Governance`, `04-Risk-Issue-Change`, and `05-Figures` folders are retained as locations for future supporting artefacts. They are intentionally empty in this package because the derivative CSVs and figures in the reference ZIP were not regenerated from the latest report; including them could falsely imply that every supporting artefact was verified against the current report.

`06-Configuration-Management/` contains repository guidance. `UPLOAD_CHECKLIST.md` lists checks to complete before uploading.

## GitHub workflow

Create the repository, then upload the **contents** of this folder (not the ZIP itself). Use meaningful commit messages, and use Issues, pull requests, and release tags only when those actions are actually performed. Do not fabricate repository activity or screenshots. Do not upload passwords, API keys, credentials, student personal data, Moodle databases or course files. Private repository visibility is the safer default unless the lecturer requires public access.

No GitHub repository URL is created or assumed by this package. This is a project-planning package, not evidence of a live LMS deployment.
